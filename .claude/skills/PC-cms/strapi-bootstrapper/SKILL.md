# Strapi Bootstrapper

Phase: **C — CMS Provisioning** (Step 2 of 4)

Initialise a production-ready Strapi 5 project and apply the generated schemas.

## Precondition

- Schema files generated by `strapi-schema-generator`

## Execution

### Step 1: Initialise Strapi Boilerplate

```bash
cd output/<site>/cms
npx create-strapi-app@latest . --typescript --quickstart
```

This creates the base Strapi v5 project structure.

### Step 2: Apply Generated Schemas

Copy generated schema files from `strapi-schema-generator` output into the Strapi project:
- `src/api/` — content type schemas, controllers, routes, services
- `src/components/` — component definitions

### Step 3: Configure Plugins

Create/update `src/config/plugins.ts`:

```typescript
export default {
  graphql: {
    enabled: true,
    config: {
      defaultLimit: 10,
      maxLimit: 100,
      apolloServer: { tracing: false },
    },
  },
  upload: {
    enabled: true,
    config: {
      provider: 'local',
      providerOptions: { sizeLimit: 262144000 },
    },
  },
};
```

### Step 4: Configure CORS & Middleware

Create/update `src/config/middlewares.ts`:

```typescript
export default [
  'strapi::logger',
  'strapi::errors',
  'strapi::cors',
  'strapi::poweredBy',
  'strapi::query',
  'strapi::body',
  'strapi::session',
  'strapi::favicon',
  'strapi::public',
];
```

### Step 5: Configure Server

Create/update `src/config/server.ts`:

```typescript
export default ({ env }) => ({
  host: env('HOST', '0.0.0.0'),
  port: env.int('PORT', 1337),
  app: { keys: env.array('APP_KEYS') },
});
```

### Step 6: Environment Configuration

Create `.env` with auto-generated keys.
If port 1337 is occupied, use an alternative and update all references.

After first admin user is created (UI registration or bootstrap script), sync runtime values into frontend env:

1. Update `output/<site>/frontend/.env.local` (create from `.env.local.example` if missing)
2. Set `STRAPI_GRAPHQL_URL`, `STRAPI_REST_URL`, and `STRAPI_URL` to the actual CMS port
3. Add **commented** admin reference lines for local visibility:

```env
# STRAPI_ADMIN_EMAIL=<email-used-at-bootstrap>
# STRAPI_ADMIN_PASSWORD=<password-used-at-bootstrap>
# STRAPI_ADMIN_URL=http://localhost:<port>/admin
```

4. Write the same summary to `output/<site>/docs/FRONTEND-ENV.md` (no secrets in git — use commented placeholders in example files only)

### Step 7: Roles & Permissions

Configure public read access for all content types:
- Enable `find` and `findOne` for Public role on each content type.
- This can be done via Strapi admin UI after first start, or via bootstrap lifecycle script.

### Step 8: Build & Verify

```bash
cd output/<site>/cms
npm install
npm run build
npm run develop
```

Verify:
- Admin UI accessible at `http://localhost:<port>/admin`
- REST API accessible at `http://localhost:<port>/api`
- GraphQL endpoint at `http://localhost:<port>/graphql`
- All content types visible in admin sidebar
- No TypeScript errors (`npx tsc --noEmit`)

## Output Contract

- Bootstrapped Strapi project at `output/<site>/cms/`
- CMS running with all content types
- Admin URL, API URL, GraphQL URL
- Build/run status
- CMS `.env` documented; frontend `.env.local.example` + `FRONTEND-ENV.md` synced with URLs and commented admin placeholders

## Downstream

Output feeds into:
- `content-etl-pipeline` (loads content into running CMS)
