# Baseline Runner

Phase: **B — Test-First Contract** (Step 2 of 2)

Run the generated test suite against the legacy source site to establish a **green baseline**. The approved test suite becomes the immutable behavioral contract for the migration.

## Precondition

- Test suite generated by `playwright-suite-generator`

## Input

- Generated test files in `output/<site>/test/tests/generated/`
- Legacy source URL

## Execution

### Step 1: Configure for Legacy Site

1. Set `baseURL` in `playwright.config.ts` to the legacy source URL.
2. Ensure all tests target the source site, not localhost.

### Step 2: Run Full Test Suite

```bash
cd output/<site>/test
npx playwright test
```

### Step 3: Capture Visual Baselines

1. Generate screenshots for visual regression tests.
2. Store baselines in `output/<site>/test/visual-baselines/`.

### Step 4: Analyse Results

Report:
- Total tests: N
- Passed: N
- Failed: N
- Skipped: N
- Pass rate: N%
- Visual baselines captured: N

### Step 5: Iterate if Needed

If pass rate is below acceptable threshold:
1. Analyse failures — are they test bugs or genuine legacy site issues?
2. Fix test bugs (locators, timing, assertions).
3. Document genuine legacy site issues as known exceptions.
4. Re-run until stable baseline is achieved.

## CHECKPOINT 2 — Human Approval Gate

After establishing a green baseline:

1. **Present results to the human** with:
   - Pass/fail summary
   - Visual baseline samples
   - Known exceptions list
   - Coverage assessment
2. **Wait for explicit approval** — the test suite becomes an **immutable behavioral contract**.
3. After approval, tests must NOT be weakened to make the new stack pass. Only the implementation may be changed.
4. **Do not proceed to Phase C until CHECKPOINT 2 is cleared.**
5. **Ensure good pass percentage on source URL** before declaring baseline ready.

## Output Contract

- Baseline test results in `output/<site>/test/test-results/`
- Visual baselines in `output/<site>/test/visual-baselines/`
- Baseline report summary
- CHECKPOINT 2 status

## Downstream

Output feeds into:
- Phase C starts after CHECKPOINT 2 clears
- Phase E: `playwright-behavioral-parity` uses same tests against new stack
